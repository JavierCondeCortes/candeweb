# Internacionalización

La web usa traducciones en tiempo de ejecución para cambiar entre español e inglés sin recargar ni generar una segunda aplicación.

## Diccionarios

Los textos de interfaz se agrupan por dominio en `src/app/core/i18n/translations`:

- `es/home_es.json` y `en/home_en.json`
- `es/candeonato_es.json` y `en/candeonato_en.json`
- `es/admin_es.json` y `en/admin_en.json`

Cada clave debe existir en ambos idiomas. En las plantillas se consume con el pipe `translate`, por ejemplo:

```html
{{ 'home.nav.community' | translate }}
```

Para añadir un apartado, se crean los dos JSON equivalentes y se registra el dominio en `i18n.types.ts` e `i18n.service.ts`.

## Contenido editorial

Los textos que escribe administración no pertenecen a los JSON. Las traducciones de cada Candeonato se guardan en `championship_translations`, una fila por edición e idioma. La API presenta `summaryEn`, `descriptionEn` y `coverAltEn` al formulario y la web utiliza español como alternativa cuando falta un valor inglés.

Esta tabla normalizada permite añadir otro idioma sin crear nuevas columnas en `championships`.

## Verificación

Ejecuta:

```bash
npm run test:i18n
```

La comprobación falla si los diccionarios ES/EN tienen claves distintas o si una referencia estática del código no existe. Las pruebas de `I18nService` también verifican el cambio inmediato, la persistencia y el fallback editorial.
